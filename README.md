# Итоговый проект: загрузка статистики грейдера в PostgreSQL

Скрипт забирает попытки студентов из API `https://api.itresume.ru/statistics/`, разбирает
`passback_params`, проверяет данные, загружает их в PostgreSQL и пишет подробный лог.
Есть оба дополнительных задания: агрегаты в Google Sheets и e-mail оповещение.

## Структура

| Файл | Что делает |
|---|---|
| `main.py` | точка входа, весь процесс по шагам, итоговый отчёт |
| `config.py` | настройки из `.env` |
| `log_setup.py` | лог в `logs/YYYY-MM-DD.log` + консоль, удаление логов старше 3 дней |
| `api_client.py` | запросы к API (период режется на интервалы, повторы при 5xx/429, ERROR со status_code) |
| `transform.py` | разбор `passback_params` через `ast.literal_eval`, валидация, пропуск плохих записей с WARNING в лог |
| `db.py` | создание таблицы, пакетная загрузка (`execute_values`), дневные агрегаты на SQL |
| `sheets.py` | доп. задание 1: выгрузка агрегатов в Google Sheets |
| `mailer.py` | доп. задание 2: письмо через `smtplib` + `ssl`, лог во вложении |

## Запуск

```bash
python -m venv venv && source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                   # вписать client_key из задания и пароль от БД
createdb grader                                        # или CREATE DATABASE grader; в psql/pgAdmin

python main.py --start 2026-05-31 --end 2026-06-01     # одни сутки
python main.py --start "2026-05-01" --end "2026-06-01" --no-email
python main.py                                         # по умолчанию — вчерашний день (UTC)
```

Даты задаются в UTC, `--end` не включается в период. Актуальные данные в API есть только до
2026-06-01, поэтому для проверки указывайте период до этой даты явно.

Таблица `grader_attempts` создаётся автоматически. Для каждой записи считается `record_hash`
(md5 от user_id + задача + тип + время), поэтому повторный запуск за тот же период дублей не создаёт.

## Валидация

Запись пропускается (с WARNING в логе), если:
- `lti_user_id` пустой или не строка;
- `attempt_type` не `run` / `submit`;
- `passback_params` не разбирается в словарь, или поле в нём не строка;
- `lis_outcome_service_url` не начинается с `http(s)://`;
- `is_correct` не `null`/`true`/`false` (`0/1` допускаются), или у `run` он не `null`;
- `created_at` не парсится как дата-время.

Лишние ключи в `passback_params` отбрасываются, отсутствующие и пустые строки (`oauth_consumer_key: ''`) пишутся как `NULL`.

## Агрегаты за день

Всего попыток, run, submit, верных submit, доля верных среди submit (%), уникальных юзеров,
уникальных задач, юзеров с хотя бы одним верным решением, попыток на юзера, пиковый час (UTC).
Пишутся в итог лога, в письмо и в Google Sheets.

## Google Sheets (доп. задание 1)

1. В Google Cloud Console создать проект, включить **Google Sheets API** и **Google Drive API**.
2. Создать сервисный аккаунт → Keys → Add key → JSON. Сохранить как `credentials.json` рядом со скриптом.
3. Создать таблицу и открыть к ней доступ (Редактор) для e-mail сервисного аккаунта (`...@...iam.gserviceaccount.com`).
4. В `.env`: `GSHEETS_ENABLED=true`, `GSHEETS_SPREADSHEET=` ключ из URL таблицы
   (`https://docs.google.com/spreadsheets/d/<КЛЮЧ>/edit`).

Если строка за день уже есть в таблице, она перезаписывается, иначе добавляется новая.

## Почта (доп. задание 2)

1. Создать ящик на mail.ru → Настройки → Безопасность → **Пароли для внешних приложений** → создать пароль.
2. В `.env`: `EMAIL_ENABLED=true`, `EMAIL_SENDER`, `EMAIL_PASSWORD` (тот самый пароль приложения),
   `EMAIL_RECIPIENTS` (через запятую).

В теме письма стоит статус (`OK` / `ОШИБКИ`), в теле итоговая сводка, лог прикладывается файлом.
